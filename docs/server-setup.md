# Конфигурация виртуальной машины devops-vm

## 1. Параметры машины

- Операционная система: Ubuntu Server 26.04.1 LTS.
- Оперативная память, видимая системе: 1,6 GiB; доступно на момент проверки — 1,2 GiB.
- Процессоры: 2.
- Корневой раздел: 12 GiB, занято 5,5 GiB, свободно 5,2 GiB.
- Swap: 2,0 GiB.
- Размер виртуального диска: не указан, требует проверки в настройках VirtualBox.

## 2. Сетевые интерфейсы

- `enp0s3` — сетевой адаптер NAT, IPv4-адрес `10.0.2.15/24`.
- `enp0s8` — сетевой адаптер Host-only, IPv4-адрес `192.168.56.102/24`.
- `lo` — локальный интерфейс `127.0.0.1/8`.

## 3. Правило проброса портов

- Протокол: TCP.
- IP хоста: `127.0.0.1`.
- Порт хоста: `2222`.
- IP гостя: не задан.
- Порт гостя: `2222`.
- Назначение: подключение к SSH виртуальной машины через localhost хостовой системы.

## 4. Учётные записи

- `devops` — рабочая учётная запись, UID 1000, домашний каталог `/home/devops`, оболочка `/bin/bash`.
- Группы пользователя: `devops`, `adm`, `cdrom`, `sudo`, `dip`, `plugdev`, `users`, `lxd`.
- Аутентификация по SSH выполняется с использованием ключа.
- Учётная запись `student` отсутствует.
- Вход по SSH от имени `root` запрещён.

## 5. Служба SSH

- Файл дополнительной конфигурации: `/etc/ssh/sshd_config.d/99-hardening.conf`.
- Порт: `2222`.
- `PermitRootLogin no`.
- `PasswordAuthentication no`.
- `PubkeyAuthentication yes`.
- `PermitEmptyPasswords no`.
- `MaxAuthTries 3`.
- `LoginGraceTime 30`.
- `AllowUsers devops`.
- `X11Forwarding no`.
- `ClientAliveInterval 300`.
- `ClientAliveCountMax 2`.

## 6. Правила межсетевого экрана

- UFW активен.
- Политика по умолчанию для входящего трафика: `deny`.
- Политика по умолчанию для исходящего трафика: `allow`.
- Маршрутизируемый трафик: `disabled`.
- `80/tcp` — `ALLOW IN` (HTTP), IPv4 и IPv6.
- `443/tcp` — `ALLOW IN` (HTTPS), IPv4 и IPv6.
- `2222/tcp` — `LIMIT IN` (SSH), IPv4 и IPv6.
- Журналирование: `medium`.

## 8. Веб-сервер

### 8.1. Устанавливаемый пакет
*   **Название пакета:** `nginx`
*   **Источник установки:** Стандартный репозиторий Ubuntu (`apt`).
*   **Команда установки:**
    ```bash
    sudo apt update && sudo apt install -y nginx
    ```

### 8.2. Путь к конфигурации ресурса
Конфигурация виртуального хоста описывается отдельным файлом, который подключается к основному конфигу Nginx через символьную ссылку.

| Файл | Путь | Назначение |
| :--- | :--- | :--- |
| Конфигурация хоста | `/etc/nginx/sites-available/devops-site` | Основной файл с блоками `server` (HTTP redirect + HTTPS). |
| Активация хоста | `/etc/nginx/sites-enabled/devops-site` | Символическая ссылка на файл из `sites-available`. Создается командой `ln -s`. |

> **Примечание для Ansible:** В роли необходимо управлять содержимым файла `devops-site` в директории `sites-available` и создавать симлинк в `sites-enabled`. Старый дефолтный конфиг (`default`) должен быть удален или переименован.

### 8.3. Каталог ресурса, владелец и права
Статическое содержимое сайта хранится в отдельном каталоге. Модель прав доступа «владелец пишет, веб-сервер читает» реализуется следующим образом:

*   **Корневая директория:** `/var/www/devops-site`
*   **Владелец (owner):** `devops` (учетная запись деплоя).
*   **Группа (group):** `devops`.
*   **Права на каталог:** `755` (`drwxr-xr-x`).
    *   Позволяет владельцу изменять содержимое.
    *   Позволяет группе и другим пользователям (включая процесс `www-data`) читать список файлов и переходить в каталог (бит `x`).
*   **Права на файлы внутри каталога:** `644` (`-rw-r--r--`).
    *   Владелец может читать и писать.
    *   Другие пользователи могут только читать.

> **Диагностика:** Если ресурс возвращает 403 Forbidden, проверьте права на каталог через `ls -ld /var/www/devops-site`. Отсутствие бита `x` у других пользователей запретит доступ к файлам даже при наличии прав `r` на сами файлы.

### 8.4. Пути к сертификату и ключу, их права
Для обеспечения HTTPS используются самоподписанный сертификат и закрытый ключ. Доступ к ним жестко контролируется для безопасности.

| Тип файла | Путь | Владелец | Группа | Права | Комментарий |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Закрытый ключ | `/etc/ssl/private/devops.key` | `root` | `root` | `600` | Секрет! Читают только root (главный процесс nginx). Рабочие процессы (`www-data`) не имеют прямого доступа. |
| Сертификат | `/etc/ssl/certs/devops.crt` | `root` | `root` | `644` | Открытая часть пары. Может читаться любым пользователем. |

> **Безопасность:** Ключ с правами `600` необходим, чтобы предотвратить утечку секрета другими пользователями системы. Главный процесс Nginx запускается от имени `root`, считывает ключ, загружает его в память рабочих процессов и затем сбрасывает свои привилегии до `www-data`.

### 8.5. Команда формирования сертификата и срок действия
Сертификат является самоподписанным (Self-Signed), так как учебный стенд недоступен из внешней сети для валидации Let's Encrypt.

*   **Срок действия:** 365 дней (`-days 365`).
*   **Алгоритм шифрования ключа:** RSA 2048 бит (`-newkey rsa:2048`).
*   **Поле SAN (Subject Alternative Name):** Обязательно содержит DNS имя `devops.local`. Современные браузеры игнорируют поле CN, если отсутствует SAN.

**Команда генерации (выполняется один раз при настройке):**

```bash
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/ssl/private/devops.key \
  -out /etc/ssl/certs/devops.crt \
  -subj "/CN=devops.local" \
  -addext "subjectAltName=DNS:devops.local"
```

**Расшифровка параметров для автоматизации:**
*   `-x509`: Генерирует сам сертификат, а не запрос на подпись (CSR).
*   `-nodes`: Не шифрует закрытый ключ паролем (passphrase), что позволяет Nginx запускаться автоматически без интерактивного ввода.
*   `-subj`: Задает данные субъекта в однострочном формате (для неинтерактивной работы).
*   `-addext`: Добавляет расширение Subject Alternative Name.

### 8.6. Процедура применения изменений
Любое изменение конфигурации Nginx или замена сертификатов требуют выполнения следующей последовательности команд:

1.  Проверка синтаксиса конфигурации:
    ```bash
    sudo nginx -t
    ```
2.  Перезагрузка сервиса (без потери активных соединений):
    ```bash
    sudo systemctl reload nginx
    ```
